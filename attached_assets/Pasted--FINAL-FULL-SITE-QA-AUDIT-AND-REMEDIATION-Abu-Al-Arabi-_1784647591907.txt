- Database Auditor

Your task is to perform a complete production-grade QA audit of the entire Abu Al-Arabi platform.

Do not only inspect the obvious pages.

Do not only write a report.

You must:

1. Discover the complete application.

2. Build a full inventory of all pages, routes, APIs, database models, roles, permissions, and workflows.

SECTION 1: FINAL PRODUCT RULES

==================================================

Treat the following decisions as final:

1. The platform is an Arabic educational platform called:

أبو العربي

2. All user-facing interfaces must be Arabic and RTL.

3. Official platform content is for Arabic language only.

4. There is no payment system.

The project must not contain active:

- checkout

- subscriptions

- invoices

- payment gateways

- Stripe

- PayPal

- Moyasar

- HyperPay

- shopping cart

- purchase flows

5. There is no private messaging system.

Allowed communication is limited to academic comments and replies where implemented.

6. There is no video system.

Remove or mark out of scope:

- video pages

- video upload

- video player

- streaming

- video analytics

- watch history

- video database tables

- YouTube/Vimeo integrations

7. There is no onboarding flow.

After authentication:

- Student → /dashboard

- Admin → /admin

8. Authentication is phone-based and passwordless.

Registration requires:

- full name

- phone number

Login requires:

- phone number

9. Jordanian phone numbers must:

- contain exactly 10 digits

- contain digits only

- start with 077, 078, or 079

Validation rule:

/^(077|078|079)\d{7}$/

10. Student primary navigation contains only:

- لوحتي

- الدوسيات

- أوراق العمل

- الامتحانات الإلكترونية

- الكويز الأسبوعي

- غرفتي الدراسية

Settings and logout may exist inside the account menu.

11. Student navigation is horizontal above the hero/banner, not a desktop student sidebar.

12. The platform has two shared internal systems:

Educational Files:

- DOSSIER

- WORKSHEET

Electronic Assessments:

- EXAM

- WEEKLY_QUIZ

Keep four separate user-facing sections.

13. Dossiers and worksheets are PDF-based files.

Both support:

- PDF download

- opening inside Study Room

- personal annotations

- persistent last page

14. Exams and weekly quizzes are electronic assessments.

Both support:

- questions

- attempts

- answers

- scores

- results

  "ok": false,

  "message": "رقم الهاتف غير صالح"

}

Verify:

- frontend prevents invalid submissions

- backend repeats validation

- phone is normalized consistently

- unique phone constraint exists

- duplicate registration behavior matches product decision

- password fields and password APIs are gone

- forgot/reset/change password are gone

- onboarding redirects are gone

- no auth retry loops

- /api/auth/me returns 200 when logged in

- cookie survives refresh

- logout destroys session

- cookie is cleared using matching options

- production does not use MemoryStore

- trust proxy is configured correctly

- credentials are included in frontend requests

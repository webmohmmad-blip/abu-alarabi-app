We have a production authentication redirect loop on malsahori.com.

Current behavior:

1. The user enters a phone number.

2. Login appears to succeed.

3. The app redirects to /dashboard.

4. The dashboard immediately redirects back to /login.

5. This repeats continuously.

The application now uses phone-only authentication with no password and no onboarding.

Do not only explain the issue. Inspect and fix the project completely.

==================================================

1. TRACE THE FULL AUTH FLOW

==================================================

Inspect:

- Login page

- Authentication API

- Session creation

- Session storage

- Cookie configuration

- /api/auth/me

- Protected route logic

- Student layout

- Dashboard redirects

- Global auth provider

- Query caching

- Production proxy configuration

Identify the exact point where the authenticated session is lost.

==================================================

2. FIX SESSION CREATION

==================================================

After successful phone login:

- Regenerate the session safely if needed.

- Assign the authenticated user ID and role to the session.

- Explicitly save the session before returning success.

- Do not redirect before session.save() completes.

Example flow:

req.session.regenerate(error => {

  if (error) return next(error);

  req.session.userId = user.id;

  req.session.role = user.role;

  req.session.save(saveError => {

    if (saveError) return next(saveError);

    res.status(200).json({

      ok: true,

      user

    });

  });

});

Use the implementation that matches the existing framework and session library.

==================================================

3. FIX PRODUCTION PROXY SETTINGS

==================================================

Because the application is deployed behind Replit or another reverse proxy:

- Enable Express trust proxy correctly.

Example:

app.set("trust proxy", 1);

Ensure this is configured before session middleware.

==================================================

4. FIX COOKIE CONFIGURATION

==================================================

Audit the production session cookie.

It must work correctly on:
https://malsahori.com

Use appropriate production settings:

- httpOnly: true

- secure: true in production

- sameSite: "lax" for same-site frontend and API

- path: "/"

- correct maxAge

- do not hardcode an incorrect domain

Prefer leaving the cookie domain undefined unless cross-subdomain sharing is actually required.

Do not use:

- localhost domain

- replit.dev domain

- an old deployment domain

- sameSite: "strict" if it breaks the flow

- sameSite: "none" unless cross-site cookies are necessary

If sameSite is "none", secure must be true.

==================================================

Ensure every authentication request includes credentials.

For fetch:

credentials: "include"

For Axios:

Apply this to:

- phone login

- /api/auth/me

- logout

- session refresh

- protected API requests

Use one centralized API client instead of inconsistent request code.

6. FIX LOGIN REDIRECT LOGIC

==================================================

The Login page must not redirect based on stale or unresolved auth state.

Use three explicit states:

- loading

- authenticated

- unauthenticated

Rules:

- While auth state is loading, show a loading state.

- If authenticated, redirect once to the correct destination.

- If unauthenticated, remain on the login page.

- Do not redirect repeatedly inside render.

- Do not combine multiple competing useEffect redirects.

- Use replace navigation after successful login.

Student:

/dashboard

Admin:

/admin

7. FIX PROTECTED ROUTES

==================================================

Protected routes must:

- Wait until /api/auth/me finishes.

- Not redirect while auth is still loading.

- Redirect to /login only after a confirmed 401.

- Avoid infinite retries.

- Avoid redirecting back and forth between layouts.

Disable automatic retry for 401 responses.

Do not silently alternate between conflicting login and registration logic.

Normalize Jordanian phone numbers consistently before lookup.

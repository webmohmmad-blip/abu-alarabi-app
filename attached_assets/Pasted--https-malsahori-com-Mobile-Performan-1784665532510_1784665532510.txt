المشكلة الأساسية المتبقية هي LCP، وليست JavaScript execution.

نفّذ إصلاحًا مركزًا ودقيقًا دون تغيير التصميم أو النصوص أو الوظائف.

==================================================

1. حدد عنصر LCP الحقيقي

==================================================

شغّل Lighthouse على النطاق الإنتاجي وحدد بدقة:

- عنصر LCP.

- اسم الملف أو الصورة.

- رابطها.

- حجمها.

- نوعها.

- وقت بدء الطلب.

- هل يتم اكتشافها من HTML أم بعد JavaScript.

- هل مصدرها CSS background-image.

- هل تنتظر API request.

- هل يوجد تحميل مكرر لها.

ضع هذه المعلومات في التقرير.

==================================================

2. اجعل LCP موجودًا في HTML الأولي

==================================================

يجب أن يكون عنصر LCP متاحًا في HTML الأولي مباشرة.

ممنوع أن يعتمد ظهور الصورة الرئيسية على:

- useEffect

- fetch بعد mount

- طلب API متأخر

- JavaScript hydration

- CSS background-image ديناميكي

- slider library

- carousel initialization

إذا كان الإعلان أو Hero يأتي من API، استخدم أحد الحلول:

- server-side injection

- server-side rendering

- cached initial payload

- inline bootstrap data في HTML

- أو fallback Hero ثابت وسريع يظهر فورًا ثم يتم تحديثه لاحقًا

المهم أن عنصر LCP لا ينتظر تشغيل React أو API.

==================================================

3. استبدل background-image بعنصر picture

==================================================

إذا كانت صورة Hero أو الإعلان تُعرض عبر:

background-image

حوّلها إلى:
<picture>
<source media="(max-width: 768px)" type="image/avif" srcset="...">
<source media="(max-width: 768px)" type="image/webp" srcset="...">
<source type="image/avif" srcset="...">
<source type="image/webp" srcset="...">
<img

    src="..."

    width="..."

    height="..."

    fetchpriority="high"

    loading="eager"

    decoding="async"

    alt="..."
>
</picture>

مع الحفاظ على نفس التصميم باستخدام object-fit وposition absolute عند الحاجة.

==================================================

4. preload صحيح ودقيق

==================================================

أضف preload للصورة الفعلية المستخدمة على الهاتف:
<link

  rel="preload"

  as="image"

  href="MOBILE_LCP_IMAGE"

  type="image/avif"

  fetchpriority="high"

/>

إذا تم استخدام srcset، استخدم:

imagesrcset

imagesizes

تأكد أن preload يطابق الصورة التي يختارها المتصفح.

ممنوع:

- preload لصورة Desktop على الهاتف

- preload لأكثر من نسخة من Hero

- preload لصورة لا تُستخدم

- preload مكرر

==================================================

5. ضغط صورة الهاتف أكثر

==================================================

الصورة المسؤولة عن LCP على الهاتف يجب أن تكون:

- AVIF أولًا

- WebP كبديل

- بعرض 480–768px فقط

- أقل من 120KB قدر الإمكان

- لا تتجاوز 180KB بأي حال إلا عند وجود سبب واضح

أزل metadata غير الضرورية.

لا ترسل PNG أو JPEG ضخم للهاتف.

==================================================

6. إزالة render-blocking resources

==================================================

التقرير يظهر تأخيرًا يقارب 1080ms.

حدد كل ملف يسبب render blocking.

نفّذ:

- inline للـ critical CSS الخاص بالهيدر وHero

- تحميل CSS غير الضروري لاحقًا

- حذف CSS غير المستخدم

- defer لكل JavaScript غير الحرج

- عدم تحميل مكتبات الصفحات الداخلية في الصفحة الرئيسية

- عدم تحميل خطوط أو أوزان غير مستخدمة

- عدم تحميل أدوات التحليل قبل ظهور المحتوى

الهدف:

تقليل render-blocking إلى أقل من 200ms.

==================================================

7. تحسين الخطوط

==================================================

استخدم فقط الأوزان اللازمة في التحميل الأول.

- WOFF2

- font-display: swap

- preload لملف خط واحد فقط إن كان ضروريًا

- إزالة أي @import للخطوط من CSS

- استخدام link preload أو self-hosted font

تأكد أن الخط لا يمنع ظهور عنوان Hero.

==================================================

8. إصلاح الكاش المتبقي

==================================================

يوجد توفير يقارب 776KB.

لملفات الصور والخطوط وJS وCSS ذات hash:

Cache-Control:

public, max-age=31536000, immutable

تأكد من ذلك على النطاق الحقيقي باستخدام Network headers.

إذا كانت صور الإعلانات بدون hash، استخدم versioned URLs أو query version:

/image.avif?v=HASH

حتى يمكن تخزينها طويلًا دون إبقاء نسخة قديمة.

==================================================

9. إزالة تحميل الصور غير الضرورية فوق fold

==================================================

على الهاتف لا تحمل:

- صور أقسام أسفل الصفحة

- thumbnails غير ظاهرة

- صور Desktop

- صور slider أخرى غير الشريحة الأولى

- صور hover

- صور preload احتياطية غير مستخدمة

حمّل فقط:

- صورة LCP

كل الباقي lazy load.

10. تحسين الإعلان/السلايدر

==================================================

- اعرض الشريحة الأولى مباشرة دون انتظار مكتبة السلايدر

- لا تحمل بقية الصور في البداية

- لا تبدأ autoplay قبل اكتمال LCP

- لا تستخدم animation ثقيل عند التحميل الأول

- لا تجعل ارتفاع Hero يعتمد على JavaScript

إذا لزم، اجعل الهاتف يعرض أول صورة ثابتة ثم فعّل السلايدر بعد load.

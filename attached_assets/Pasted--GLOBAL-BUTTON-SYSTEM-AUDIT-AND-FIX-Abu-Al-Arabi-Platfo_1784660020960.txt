# GLOBAL BUTTON SYSTEM AUDIT AND FIX

# Abu Al-Arabi Platform

You are a senior frontend engineer, design-system architect, accessibility specialist, and QA engineer.

There is a repeated contrast problem across the website where some buttons have unreadable combinations such as:

- white text on white background

- light text on light background

- invisible hover state

- invisible active state

- disabled text that cannot be read

- transparent button on a light page with white text

This issue has appeared in multiple places, including:

- Exams filter buttons

- Submit Exam button

- Advertisement forms

- Hero buttons

- Admin pages

- Other action buttons

Do not patch individual buttons separately.

Audit and repair the entire button system globally.

==================================================

PART 1: DISCOVER THE BUTTON ARCHITECTURE

==================================================

Inspect the project and identify:

- shared Button component

- button variants

- Tailwind utility classes

- CSS modules

- global CSS variables

- theme tokens

- dark/light mode overrides

- Radix UI buttons

- shadcn/ui Button component

- custom buttons

- icon buttons

- filter buttons

- segmented controls

- tabs that visually behave like buttons

- submit buttons

- links styled as buttons

Create an inventory of all button sources.

Determine whether the repeated bug comes from:

- wrong variant definitions

- inherited text color

- global `.text-white`

- theme overrides

- active state styles

- disabled state styles

- dark-mode classes applied on light backgrounds

- inconsistent ad-hoc Tailwind classes

PART 4: BUTTON VARIANTS

==================================================

Primary:

- background: #5A2D82

- text: #FFFFFF

- border: #5A2D82

- hover background: darker purple

- active background: darker than hover

- focus ring: visible purple ring

- disabled: reduced opacity but readable

Secondary:

- background: #0D9BB5

- text: #FFFFFF

- border: #0D9BB5

- hover: darker turquoise

Outline:

- background: transparent or white

- text: #5A2D82

- border: 1px solid #5A2D82

- hover background: light purple

- hover text: #5A2D82

Ghost:

- background: transparent

- text: readable according to surrounding background

- hover background: subtle visible surface

- never white text on light background

Success:

- background: #2FA84F

- text: #FFFFFF

Warning:

- background: #C79A2D

- text: use #1F2937 if white fails contrast

- ensure WCAG AA

Destructive:

- background: #DC2626

- text: #FFFFFF

Neutral:

- background: #FFFFFF

- text: #1F2937

- border: #D1D5DB

Link:

- background: transparent

- text: #5A2D82

- underline on hover or clear hover state

Icon-only:

- must have visible hover

- must have aria-label

- must not rely on icon color alone

==================================================

PART 5: STATE RULES

==================================================

For every variant, define:

- default

- hover

- active

- focus

- focus-visible

- disabled

- loading

- selected

- unselected

Never allow:

- bg-white + text-white

- bg-transparent + text-white on light background

- hover:bg-white + hover:text-white

- disabled text becoming invisible

- selected state losing contrast

- focus ring missing

- loading spinner without readable label

PART 13: ACCESSIBILITY

==================================================

Target WCAG 2.1 AA.

Verify:

- sufficient color contrast

- visible keyboard focus

- correct disabled semantics

- icon-only buttons have aria-label

- loading buttons have accessible status

- active state is not shown by color alone

- all buttons are keyboard accessible

- no clickable div without keyboard support

==================================================

PART 14: SEARCH FOR BAD PATTERNS

==================================================

Search the entire codebase for patterns such as:

- bg-white text-white

- text-white bg-transparent

- hover:bg-white hover:text-white

- disabled:text-white

- data-[state=active]:bg-white

- data-[state=active]:text-white

- className strings that override shared variants

- inline styles with color: white on light backgrounds

- duplicate custom button components

Fix all confirmed issues.

==================================================

PART 15: DESIGN SYSTEM IMPLEMENTATION

==================================================

Prefer a reusable component API such as:
<Button variant="primary" size="md">

  حفظ
</Button>

Supported sizes:

- sm

- md

- lg

- icon

Avoid repeated raw class strings across pages.

If the project uses class-variance-authority, define all variants centrally.

If the project uses Tailwind, use semantic tokens rather than ad-hoc colors.

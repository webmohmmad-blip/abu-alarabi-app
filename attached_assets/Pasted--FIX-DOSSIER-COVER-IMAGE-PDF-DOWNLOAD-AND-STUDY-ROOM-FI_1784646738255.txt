# FIX DOSSIER COVER IMAGE, PDF DOWNLOAD, AND STUDY ROOM FILE OPENING

# Abu Al-Arabi Platform

There are three production bugs on the dossier details page:

1. The uploaded dossier cover image does not appear.

2. Clicking "تحميل PDF" does not download the file to the device.

3. Clicking "ادرس الآن في غرفة الدراسة" returns a file error.

Do not only explain the issue.

Inspect and fix the complete file flow end-to-end:

- Admin upload form

- File storage

- Database values

- Public file URLs

- Dossier API responses

- Cover image rendering

- PDF download behavior

- Study Room PDF loading

- Production deployment configuration

==================================================

1. TRACE THE FILE DATA FLOW

==================================================

Inspect how the admin uploads:

- dossier PDF

- cover image

Trace these values through:

1. Frontend form

2. Upload API

3. Storage provider

4. Database

5. Dossier API

6. Student dossier page

7. Download button

8. Study Room

Identify whether the application stores:

- blob: URLs

- temporary local paths

- localhost URLs

- replit.dev preview URLs

- expired signed URLs

- incorrect relative paths

- filenames without public URLs

- fake placeholder values

These must not be used in production.

==================================================

2. FIX FILE STORAGE

==================================================

Files must be stored in persistent production storage.

Do not rely on:

- browser blob URLs

- temporary filesystem paths

- local development folders

- frontend-only object URLs

Use the existing persistent object storage solution in the project.

If no persistent object storage exists, implement one compatible with the current deployment.

Store at minimum:

Dossier:

- coverImageUrl

- pdfFileUrl

- pdfFileName

- pdfMimeType

- pdfSizeBytes

- storageKey

The database must store stable references, not temporary URLs.

==================================================

3. FIX COVER IMAGE DISPLAY

==================================================

The dossier page currently displays a broken or empty image.

Requirements:

- Read the actual coverImageUrl from the API.

- Validate that the URL is non-empty.

- Render it with the correct image component.

- Use a valid fallback only when no cover was uploaded.

- Do not show a broken-image icon.

- Preserve the correct aspect ratio.

- Use object-fit: cover.

- Add an Arabic alt value using the dossier title.

- Handle loading and error states.

If using an image optimization component, whitelist the storage domain or use the correct unoptimized configuration where required.

Test:

- uploaded JPG

- JPEG

- PNG

- WebP

- missing cover

- replaced cover

- deleted cover

==================================================

4. FIX PDF DOWNLOAD

==================================================

The "تحميل PDF" button must download the actual file to the student's device.

Do not only open a broken URL.

Preferred behavior:

- Call a secure download endpoint.

- Validate access.

- Return or redirect to the correct file.

- Use proper response headers:

Content-Type: application/pdf

Content-Disposition: attachment; filename="safe-file-name.pdf"

If the storage provider uses signed URLs:

- Generate a fresh signed download URL on demand.

- Do not store expired signed URLs permanently in the database.

Frontend behavior:

- Show loading state while preparing the download.

- Disable duplicate clicks.

- Start the download.

- Show an Arabic error message if it fails:

"تعذر تحميل الملف، حاول مرة أخرى"

The button must work on:

- Chrome

- Safari

- iPad

- iPhone

- Android

- Desktop

==================================================

5. FIX STUDY ROOM OPENING

==================================================

When clicking:

"ادرس الآن في غرفة الدراسة"

the selected dossier PDF must open automatically in the Study Room.

Expected flow:

1. User clicks the button.

2. Navigate to a route such as:

/study-room?dossierId=:id

or:

/study-room/dossiers/:id

3. The Study Room requests dossier metadata from the backend.

4. The backend validates the logged-in user's access.

5. It returns a valid PDF viewing URL.

6. The PDF reader loads the document.

Do not pass a temporary blob URL through navigation state.

Do not depend on a stale frontend URL.

==================================================

6. PDF VIEWING ENDPOINT

==================================================

Create or verify a secure endpoint such as:

GET /api/dossiers/:id/view

Response options:

A. Redirect to a fresh signed viewing URL.

or

B. Stream the PDF with:

Content-Type: application/pdf

Content-Disposition: inline

The endpoint must:

- require authentication if the dossier is private

- verify the dossier exists

- verify a PDF is attached

- return 404 if no file exists

- return 403 if access is denied

- return a safe Arabic error response

Example:

{

  "ok": false,

  "message": "ملف الدوسية غير متوفر"

}

==================================================

7. CORS AND RANGE REQUESTS

==================================================

The PDF reader may require HTTP Range requests.

Ensure the PDF source supports:

- Accept-Ranges: bytes

- Range requests

- partial content responses where applicable

- correct CORS headers for the production domain

Allow only the required origin:
https://malsahori.com

Do not use a wildcard with credentials.

Verify that the storage provider or proxy supports PDF.js range requests.

==================================================

8. API RESPONSE CONSISTENCY

==================================================

Make sure the dossier API returns consistent fields.

Example:

{

  "id": "...",

  "title": "...",

  "description": "...",

  "coverImageUrl": "...",

  "pdfAvailable": true,

  "pdfFileName": "...",

coverUrl

image

imageUrl

from different endpoints.

Choose one canonical contract and update frontend and backend to match.
